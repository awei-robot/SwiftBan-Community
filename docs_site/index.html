为什么是 SwiftBan

fail2ban 配置复杂、云 WAF 成本高。SwiftBan 用 2000 行 Bash 做好了"读日志 → 识别攻击 → 封 IP"这一件事，并把"不误伤正常业务"作为第一原则。

🎯

零误封设计

只封明确攻击特征；高频请求仅记录观察（WATCH）；双层白名单支持 CIDR 网段；内网网关默认放行。

📦

零依赖轻量

纯 Bash + gawk，无需 Python/Go 运行时。10 万行日志单次扫描 < 5 秒，内存 < 10MB。

🐳

Docker 原生适配

自动写入 DOCKER-USER 链——Docker 端口映射流量走 FORWARD，普通 INPUT 规则根本拦不住。

🔍

11 维度检测

444 扫描、404/400 探测、恶意路径（wp-admin/.env/.git）、SQL 注入/XSS/Log4j 载荷、sqlmap 等 14 种扫描器 UA、登录爆破、单接口速率（CC）、空 UA。

⏱️

自动解封与恢复

TTL 到期自动解封（默认 3 天）；服务器重启或规则被清空后自动重建；状态文件持久化。

🌐

时区安全

全程 UTC 时间戳精确过滤。曾因 8 小时时区偏差导致窗口统计恒为 0 的坑，已彻底解决。

社区版 vs 商业版

社区版永久免费开源（MIT）。需要 Web 管理台、Windows 服务器防护或多机集中管理时，升级商业版。

5 分钟部署

三步完成。支持 cron 每分钟执行，或 systemd timer 常驻。

克隆并安装

安装脚本自动检查依赖（iptables / gawk），复制程序到 /usr/local/bin。

配置日志目录与白名单

编辑 /etc/swiftban/swiftban.conf，指向 Nginx/NPM 日志目录，填入内网可信 IP。

演练模式观察，再正式启用

swiftban run --dry-run 只检测不封禁；确认无误封后安装 cron 或 timer。
