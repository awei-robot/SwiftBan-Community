# SwiftBan 配置说明

配置文件路径：`/etc/swiftban/swiftban.conf`（可用 `SWIFTBAN_CONF` 环境变量覆盖）

## 一、日志与状态

```ini
LOG_DIR="/root/proxy-manager/data/logs"   # Nginx/NPM 日志目录
LOG_FORMAT="auto"                        # auto / npm_standard / npm_proxy / combined
STATE_DIR="/etc/swiftban/state"           # 状态目录（封禁列表/日志/白名单）
```

支持 NPM standard、NPM proxy 和 Nginx 默认 combined。auto 逐行识别，允许目录内混合格式；显式指定格式时，其他格式的记录会被跳过。NPM proxy 读取最终响应状态，支持缓存状态、缺失上游及多次上游重试。引号内的伪造客户端标记不会被视为真实 IP。

只扫描目录第一层最近3分钟内修改过的普通文件（`find -mmin -3`）：活动文件 `*access.log`、数字轮转后缀（如 `access.log.1`）、日期后缀（如 `access.log-20261116`、`access.log.2026-11-16`）。不读取 gzip、任意自定义格式、JSON 或 syslog，也不递归扫描子目录。文件修改时间只用于预筛选，入选文件仍按日志条目时间及 WINDOW 过滤。即使条目仍在 WINDOW 内，文件超过3分钟未修改也不参与本轮统计；增大 WINDOW 不会扩大文件修改时间范围。

同一 inode 只读一次。同一活动日志及轮转文件组成一个日志家族；家族内完全相同的行按各文件中的最大出现次数统计，防止 copytruncate 重叠双倍计数，同时保留单文件中的重复行。这是偏向避免误封的保守策略，可能少计跨轮转边界完全相同的合法重复行。

每轮按来源输出有效、格式错误、过期、未来、重复数量；有效数量包含随后去重的记录，最终窗口行数为去重后的数量。未知格式和非法 IP/日期/控制字符记录跳过，不生成候选；文件枚举、读取或解析程序执行失败则中止本轮新增封禁并返回非零。正常运行先完成历史恢复和 TTL 解封，避免读取故障阻断维护。

## 二、检测窗口

```ini
WINDOW=7200    # 正整数秒；按日志中的时区偏移换算为 UTC
```

仅统计 `now - WINDOW <= 日志时间 <= now`，包含两端边界，拒绝未来时间。分钟速率按 UTC epoch 分钟分组，同一时刻的不同日志时区不会拆分计数。

| 窗口 | 适用场景 |
|------|---------|
| 300 | 5 分钟，快速响应（阈值需相应降低） |
| 7200 | **默认**，2 小时，平衡灵敏度与误封 |
| 86400 | 24 小时，宽松模式 |

## 三、封禁阈值

| 参数 | 默认 | 说明 |
|------|------|------|
| `LIMIT_444` | 10 | 域名扫描（444 次数） |
| `LIMIT_SCAN` | 100 | 404/400 扫描次数 |
| `LIMIT_EVILPATH` | 3 | 恶意路径/敏感文件次数 |
| `LIMIT_PAYLOAD` | 2 | 漏洞载荷次数 |
| `LIMIT_UA` | 5 | 可疑 UA 次数 |
| `LIMIT_AUTH` | 20 | 登录爆破（登录路径 401/403） |
| `LIMIT_API` | 200 | IP + 域名 + 完整 URI 的窗口内总量；超限只记录 WATCH，不单独封禁 |
| `LIMIT_API_RATE` | 30 | 同一 IP、域名和完整 URI 每个 UTC 分钟的请求数；超限只记录 WATCH 告警，不单独封禁，避免共享 NAT 出口误伤 |
| `LIMIT_EMPTYUA` | 20 | 空 UA 次数 |
| `LIMIT_HIGHFREQ` | 500 | 高频观察（仅记录，不封禁） |

> 单接口分组保留查询参数，例如 `/api?a=1` 和 `/api?a=2` 分开统计。NPM 域名转为小写；combined 没有域名字段，使用日志家族的文件标识隔离站点。同一个 combined 文件包含多个站点时无法进一步区分。

> 阈值调整建议：先执行 dry-run，检查格式错误数量及候选记录，再根据实际流量调整。

`WINDOW` 和各 `LIMIT_*` 必须为 1–2147483647 的十进制整数，`BAN_TTL` 同范围且允许 0 表示永久；不接受负数、前导零或算术表达式。特征正则不能为空且必须能由当前 AWK 编译。

## 四、封禁策略

```ini
BAN_TTL=259200              # 封禁时长（秒），0=永久
FIREWALL_CHAIN="DOCKER-USER" # 防火墙链
```

| 场景 | 链 |
|------|-----|
| Docker 端口映射（NPM 等） | `DOCKER-USER`（默认，必须） |
| 裸机 Nginx | `INPUT` |

`iptables` 是必需依赖，缺失时安装终止。`ip6tables` 和 IPv6 对应防火墙链均为可选；命令未安装，或配置链（如 Docker 未启用 IPv6 时缺少 `DOCKER-USER`）不可用时，安装和配置检查只提示并忽略 IPv6，IPv4 继续运行。自动检测跳过 IPv6 封禁并保留其状态记录；手动 IPv6 封禁仍返回失败，不会写入未成功封禁的状态。链缺失不会中断 IPv4 新增封禁。`doctor` 会报告 IPv6 降级警告。

安装程序会显示当前 `LOG_DIR` 和 `FIREWALL_CHAIN`，允许直接回车保留，或输入新值并写入 `/etc/swiftban/swiftban.conf`。Docker 端口映射一般选 `DOCKER-USER`，裸机 Nginx 一般选 `INPUT`；确认后会执行配置检查，检查通过才继续安装定时任务。

## 五、白名单

```ini
# 内置（逗号分隔，精确匹配）
WHITELIST="127.0.0.1,::1,192.168.224.1,172.17.0.1"

# 独立文件（IP/CIDR，动态生效，优先级更高）
WHITELIST_FILE="/etc/swiftban/state/whitelist.txt"
```

白名单文件格式：
```
# 注释
192.168.1.100          # 单 IP
10.0.0.0/8             # 整个网段
203.0.113.0/24         # 特定网段
```

CIDR 仅支持 IPv4，掩码必须是 0–32 的十进制整数；地址各段为 0–255，不接受前导零。添加非法 CIDR 会报错，已有文件中的非法 CIDR 不匹配任何地址。IPv6 目前使用精确地址匹配。

`swiftban whitelist add <IP/CIDR>` 会先验证并规范化地址；IPv6 压缩/展开形式及相同 IPv4 网段不会重复写入，CIDR 保存为网络地址。添加和删除通过同目录临时文件原子替换，保留注释、其他条目和原文件权限。添加成功后会撤销命中白名单的已有封禁（CIDR 覆盖整个网段）并清理 banlist；撤销失败保留对应记录并返回失败，可重复添加重试。状态修改遇到正在执行的扫描时最多等待 60 秒，超时返回失败。`remove` 接受等价的 IPv6 或 CIDR 写法，并删除对应条目及其行内注释；内置 `WHITELIST` 需在配置文件中修改。

IPv6 的压缩、展开和大小写写法按同一个地址处理，日志统计和新封禁记录使用统一展开形式；使用任意等价写法手动解封会同时删除旧 banlist 中的等价记录。IPv4 映射地址按等价 IPv6 写法比较，与纯 IPv4 地址仍保持区别。

## 配置检查与定时安装

`swiftban configtest` 在阈值、TTL、正则或白名单非法，日志目录不可读取，状态目录不可读写，白名单文件不可读取，iptables 缺失或配置链不可查询时返回非零。已安装 ip6tables 时也检查对应链；未安装则提示可选功能降级。查询防火墙需足够权限，建议使用 `sudo swiftban configtest`。安装器验证失败不会安装新的 cron。

`sudo swiftban doctor` 汇总必需命令、配置与白名单、目录权限、banlist 格式、防火墙链和本实例规则、启停状态以及当前用户 cron 和标准 `swiftban.timer`。关键检查失败时返回非零；可选 IPv6 缺失、正式检测已停止或未安装定时任务会显示警告，并附常见修复命令。命令只读取系统和 SwiftBan 状态，不修改防火墙或调度配置。

`swiftban install-cron` 需要 root，使用当前入口、当前 `SWIFTBAN_CONF` 及配置中的状态目录生成任务；路径包含空格或单引号时安全引用，百分号及控制字符会被拒绝。配置文件路径写入任务，避免 cron 丢失调用时的环境变量。重复安装相同任务保持一条，其他配置的任务和注释保留。读取或写入 cron 失败会明确返回非零。启用多个配置时应分别设置状态目录。

## 六、特征库

```ini
SAFE_PATH='/TDT/'       # 正常路径（404 不计入扫描）
GIT_SAFE='git-upload-pack|git-receive-pack|info/refs'
EVIL_PATH='...'         # 恶意路径正则
EVIL_PAYLOAD='...'      # 漏洞载荷正则
EVIL_UA='...'           # 可疑 UA 正则
LOGIN_PATH='login|signin|auth|token'
```

**字段边界**：`EVIL_PATH`、`SAFE_PATH`、`LOGIN_PATH`、`GIT_SAFE` 只匹配 URI 路径，不包含查询参数。`EVIL_UA` 仅匹配 UA；空 UA 同时识别 `"-"` 和 `""`。`EVIL_PAYLOAD` 分别匹配完整 URI、UA、Referer，不跨字段拼接。保留日志转义文本，不额外进行 URL 解码。

Git 路径排除只依赖路径；载荷规则原有的 `git.43tc.cn` 排除只接受 Host 精确匹配，不接受后缀域名或其他字段中的同名字符串。

**注意**：修改正则时需转义特殊字符（如 `.` → `\.`），建议保持默认值。

## 七、配置检查

```bash
swiftban configtest
```

该命令会校验 `LOG_FORMAT` 枚举及 `WINDOW` 正整数约束，并显示选定格式。

必需模块缺失、不可读或加载失败时会返回非零，并显示具体文件路径。安装程序在这些检查通过后才创建 cron；从源码运行安装脚本时应使用同一版本的 CLI 和全部库文件。

## 八、演练模式

正式启用前建议先演练（只检测不封禁）：

```bash
swiftban run --dry-run
```

观察输出中 `[DRY-RUN] 将封禁 ...` 的记录，确认无误判后再开启正式模式。dry-run 不恢复规则、不解封、不修改 banlist 或防火墙，候选中也排除白名单及已生效封禁 IP。演练会写运行元数据，并将最近一次完整候选原子保存到 `${STATE_DIR}/dry-run.tsv`；成功且零候选时也更新，失败或中断保留上次完整结果。记录包含 run ID、UTC 起止时间、格式、日志目录、3 分钟文件修改筛选、条目时间窗口、各规则阈值、参与文件清单及每个文件的有效/无效/过期/未来/重复计数。

```bash
swiftban list --dry-run     # 复核运行 ID、输入范围、配置摘要、解析计数和候选
```

该文件只供查看，不进入 banlist 恢复流程。普通 `list` 仍显示原封禁记录；停止状态下记录待恢复，不能据此认定当前防火墙仍在封禁。

`--dry-run` 只作用于本次命令，既不修改全局模式，也不改变已有定时任务。安装器和默认 systemd 示例配置的是正式 `run`；如需周期演练，必须在任务中明确使用 `run --dry-run`。

升级前请使用目标 NPM/Nginx 版本的脱敏日志验证所有实际格式，检查格式错误计数及候选 IP。合成样例测试通过不能替代生产日志验收；已有封禁不会自动清除，阈值不会自动调整。

## 九、启停与恢复

```bash
sudo swiftban stop
sudo swiftban start
swiftban status
```

`stop` 先持久写入停止标记，再终止当前扫描的独立会话及子进程，撤销本实例标记的规则和当前配置链中与 banlist 精确对应的历史无标记 DROP。它不清空共享防火墙链、不删除其它实例标记的规则、不改写 banlist 的时间戳、TTL 或原因。

cron/systemd 配置保持原样，后续正式 `run` 因停止标记跳过，机器重启后仍保持停止。显式 `run --dry-run` 仍可运行（包括明确配置为演练的任务）；手动 `ban` 被拒绝，手动 `unban` 可取消待恢复记录。扫描正在执行时，手动状态修改返回繁忙，避免竞争写入。

停止期间 TTL 继续计时，TTL=0 仍表示永久。`start` 清理已过期记录、跳过白名单、恢复其余规则，成功后解除停止标记并立即正式扫描。IPv4 恢复失败会回滚本次恢复并保持停止；已有扫描运行时不会重复启动。

过期记录不参与恢复；随后立即执行的新检测若再次满足规则，仍可能对同一 IP 产生新的封禁，这与恢复旧记录是两件事。

缺少可选 ip6tables 时，IPv4 可正常恢复，IPv6 记录保留并提示降级；无法确认过期 IPv6 规则是否撤销时，过期记录也保留等待核验，但不会恢复。若 `stop` 无法确认历史 IPv6 规则、删除失败、进程身份不可信或扫描未退出，会返回非零并显示“停止未完成”。排除问题后重复 `stop` 完成清理，再执行 `start`。

升级前的旧扫描没有新运行元数据时，停止操作不会猜测 PID 或使用宽泛的 pkill。应等待旧任务退出后重试；不要删除锁文件来绕过正在运行的扫描。

## 十、状态与运行文件

`status` 分别展示：

- 控制状态：启用、已停止、正在恢复、正在停止或停止未完成。
- 当前执行：由运行锁、进程启动时间、独立会话和本次系统启动标识共同确认，包含模式、PID、开始时间及阶段；残留元数据不等于正在运行。
- 最近执行：模式、开始/结束时间、完成/失败/中断结果；当前运行和最近一次记录分别显示。
- 定时配置：当前用户可识别的 cron 原始命令、标准 `swiftban.timer` 的启用/活动状态及服务命令。复杂调用、自定义单元或权限不足时明确表示无法可靠确认，不能据此断言未配置其他任务。
- 保存记录与实际管理规则数，以及最近一次完整演练结果时间。最近一次演练不代表 cron 的正式任务也处于演练模式。

新增运行文件均位于 STATE_DIR：`stopped.tsv`（停止门控）、`active.tsv`（当前会话身份）、`last-run.tsv`（最近一次扫描）、`dry-run.tsv`（完整演练结果）、`.instance-id`（规则归属标识）及内部锁文件。文件按固定格式读取，不作为 shell 代码执行；不要手工 source、篡改或删除运行文件，也不要将演练候选复制进 banlist。

启停需要 Linux /proc、Bash 4.1+、flock 和 setsid，通常由 util-linux 提供；`start`、`stop` 和封禁修改需要 root。状态查询权限不足时显示无法读取，不以“0 条”推断不存在规则。定时模式显示以原始任务命令为准。


## WATCH 观察记录

单接口高频（`api`）、单接口速率（`apirate`）及总请求高频（`freq`）超限仅观察，不单独触发封禁。终端仍输出 WATCH，同时在完整扫描后保存独立观察记录。

```bash
swiftban watch                          # 正式扫描近24小时，最多50项
swiftban watch --ip 123.114.230.31       # 指定IP，支持等价IPv6写法
swiftban watch --rule api               # api / apirate / freq
swiftban watch --since 7d --limit 100    # 时间范围（h或d）及条数
swiftban watch --dry-run                # 演练观察记录
swiftban watch --json                   # JSON导出，可组合上述筛选
```

列表按最近发现时间倒序，显示 IP、规则、最近计数/当时阈值、峰值、命中轮次、首次/最后发现时间（UTC）、统计窗口秒数和接口。按 IP＋规则＋域名及完整 URI 聚合；总请求高频只按 IP 分组。计数采用该次扫描的统计值，**不跨扫描相加**，因为扫描窗口可能重叠；命中轮次表示触发观察的扫描次数。单接口速率在同一扫描内有多个分钟超限时取最大分钟计数，只计一个命中轮次。首次、峰值和轮次均基于本次查询时间范围，接口保留查询参数。

正式与演练分别存储于 `${STATE_DIR}/watch/formal/日期/` 和 `watch/dry-run/日期/`，每次完整扫描原子发布一个文件。零命中扫描仍保留完成元数据；失败或中断的扫描不会发布中间结果。查询不申请扫描锁。保存失败会告警并使扫描返回非零，已完成的防火墙操作不会因此回滚。

`WATCH_RETENTION_DAYS=7` 控制保留天数，必须是正整数，默认7天。扫描发布结果时按记录时间清理两种模式的过期文件；停止扫描期间不自动清理。查询范围大于保留期也无法找回已清理记录。目录权限为700、记录文件为600，完整URI可能包含敏感查询参数，请按需限制状态目录访问。

观察历史不因加入白名单或其他规则封禁而删除，也不会自动升级为封禁。`status` 显示正式和演练的最近扫描及近24小时命中IP数；`doctor` 检查观察目录权限和文件格式。升级前的 WATCH 文本输出无法自动转为结构化历史，完成新扫描后才可查询。


## 单 IP 原始访问复核

`swiftban list --ip <IP> [--since 2h] [--limit 100]` 直接查询 `LOG_DIR` 中的原始访问日志，以解析出的客户端 IP 规范化后精确匹配，支持 IPv4/IPv6。显示来源文件与行号、完整原始行，以访问时间从新到旧排序。原文保留请求方法、完整 URI、状态码、UA 和 Referer 等已有字段，不进行日志转义解码。URI/UA/Referer 中出现的目标 IP 不会被误认为客户端。

默认时间范围为 `WINDOW` 秒，默认100条；`--since` 接受正整数加 `m`、`h` 或 `d`，`--limit` 为1–999999。仅读取目录第一层最近3分钟修改的支持格式日志及未压缩轮转文件，与自动检测共用文件筛选和解析器。修改 `--since` 不会改变3分钟文件修改筛选。查询不读取压缩文件，也不恢复已删除日志；没有匹配不代表没有历史访问。

原始记录查询不做跨文件轮转去重，来源与行号对应本次读取；扫描期间日志追加或轮转可能改变可见范围。无效和未来日志被排除；输出汇总命中条数及候选文件格式无效记录数。读取或解析失败返回非零，不展示不完整结果。命令不修改封禁/白名单/观察状态、不申请扫描锁。封禁原因仍使用 `swiftban list` 查看，聚合观察详情使用 `swiftban watch --ip <IP>` 查看。
