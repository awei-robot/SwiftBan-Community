# SwiftBan 社区版 v1.0.2

发布日期：2026-11-16

本版本重点修复访问日志解析中的错误封禁候选和漏检问题，统一支持 Nginx Proxy Manager standard/proxy 与 Nginx combined 格式，并将文件收集限制为最近 3 分钟修改的日志。iptables 仍为必需依赖，ip6tables 改为可选。

建议使用 NPM、缓存或上游重试、非 UTC 日志，以及仅部署 IPv4 防火墙的用户升级。此次不改变默认阈值、封禁状态文件格式或已有封禁记录。

## 关键修复

### 1. 客户端身份与字段解析

- 从格式规定的客户端位置提取并校验完整 IPv4/IPv6，不再对整行搜索所有 `[Client ...]`。
- 修复 UA 等用户可控字段中嵌入伪造客户端标记后，无关 IP 进入封禁候选的问题。
- 修复 NPM standard 将客户端 IP 当作 URI，导致不同接口被合并计数的问题。
- NPM proxy 读取最终响应状态码，不再将上游状态当作最终状态；兼容 HIT/MISS 等缓存状态、无上游响应及多次上游重试。
- 支持 Nginx 默认 combined 格式；自动模式允许目录内混合格式。
- 正确识别带空格的引号字段、转义文本、IPv6 Host、空字符串 UA，以及已识别格式末尾的扩展字段。保留转义文本，不额外进行 URL 解码。

### 2. 时间窗口与接口分组

- 按日志的 `±HHMM` 偏移换算 UTC，避免将所有日志日期直接当作 UTC。
- 严格校验日期，只统计 `now - WINDOW <= epoch <= now` 的记录，拒绝未来时间。
- 单接口按“IP + 域名 + 完整 URI”分组，查询参数保留，例如 `/api?a=1` 和 `/api?a=2` 分开统计。
- 分钟速率按 UTC epoch 分钟统计，同一时刻的不同日志时区不会拆分分组。
- combined 没有 Host 字段，使用活动日志文件家族标识隔离站点；同一 combined 文件内的多个站点无法进一步区分。

### 3. 检测规则限定字段

| 配置或规则 | 本版本匹配范围 |
|---|---|
| `EVIL_PATH`、`SAFE_PATH`、`LOGIN_PATH`、`GIT_SAFE` | URI 路径，不含查询参数 |
| `EVIL_UA` | UA 字段 |
| `EVIL_PAYLOAD` | 完整 URI、UA、Referer 分别匹配，不跨字段拼接 |
| 空 UA | `"-"` 和 `""` |

UA、Referer 或查询参数中的安全路径/Git 词不再影响路径排除规则；访问 `/docs/sqlmap` 不会仅因为路径包含 sqlmap 就被计为可疑 UA。载荷规则原有的 `git.43tc.cn` 排除改为 Host 精确匹配，不接受其他字段中的同名文本或后缀域名。

## 日志收集与失败处理

- 只读取日志目录第一层、最近 3 分钟内修改的普通文件，即 `find -mmin -3`。
- 支持活动文件 `*access.log`、数字轮转（如 `.1`）及日期轮转（如 `-20261116`、`.2026-11-16`）；不读取 `.gz` 或子目录。
- 文件修改时间用于预筛选；入选文件仍按日志条目时间及 `WINDOW` 过滤。即使条目仍在窗口内，文件超过 3 分钟未修改也不参与本轮统计；增大 WINDOW 不会扩大这个文件筛选范围。
- 同一 inode 只读取一次。同一日志家族跨文件的完全相同行，按各文件中的最大出现次数统计，避免 copytruncate 重叠双倍计数，同时保留单文件的重复请求。这种保守去重可能少计轮转边界上完全相同的独立请求。
- 按来源报告有效、格式错误、过期、未来和重复数量。有效数量包含随后去重的记录，最终窗口行数为去重后的数量。
- 未知格式及非法 IP、日期、控制字符记录跳过，不生成候选；文件枚举、读取、解析程序或统计失败时，停止本轮新增封禁并返回非零。
- 正常运行先恢复历史规则和清理 TTL 到期状态，再扫描日志。dry-run 不恢复、不解封、不写封禁状态，并排除白名单和已封禁 IP。

## 配置与安装变化

新增配置，旧配置缺省时自动使用 `auto`：

```bash
LOG_FORMAT="auto"  # auto / npm_standard / npm_proxy / combined
```

- 显式指定格式时，其他格式的记录会被跳过；JSON、syslog 和任意自定义格式暂不支持。
- `configtest` 校验 LOG_FORMAT 枚举和 WINDOW 正整数约束，并显示 IPv6 工具是否存在。
- 修正模块安装位置与 CLI 加载目录不一致的问题，模块统一安装到 `/usr/local/lib/swiftban/`。
- awk 检查同时验证 `mktime` 和区间正则，优先使用 gawk；不支持的解释器不能跳过测试后报告成功。
- **iptables 必须存在**，缺失时安装终止。
- **ip6tables 可以不存在**，缺失时提示 IPv6 封禁不可用，IPv4 继续正常运行；IPv6 封禁失败不写入封禁状态，IPv6 计数为 0。若安装 ip6tables，仍需确保对应 IPv6 链可用。

## 安装与升级

运行环境为 Linux + root + iptables + gawk，或具备所需能力的较新 mawk。Docker 端口映射场景使用 `DOCKER-USER`，裸机 Nginx 按实际流量路径选择 `INPUT`。

升级前备份 `/etc/swiftban/swiftban.conf` 和实际 STATE_DIR 中的状态、白名单及审计文件。先暂停现有 cron/systemd 调度，避免安装或校验期间执行检测；不要清空现有封禁状态。

```bash
git clone --branch v1.0.2 --depth 1 \
  https://github.com/awei-robot/SwiftBan-Community.git SwiftBan-Community-v1.0.2
cd SwiftBan-Community-v1.0.2
sudo bash install/install.sh
```

安装询问是否安装 cron 时先选择 `n`。已有配置会保留，随后检查日志目录、白名单、防火墙链及格式：

```bash
sudo swiftban version       # 应输出 SwiftBan v1.0.2
sudo swiftban configtest
sudo swiftban run --dry-run
```

请使用目标 NPM/Nginx 版本的脱敏真实日志确认解析计数和候选 IP，再恢复原有调度。首次部署可在验证后执行 `sudo swiftban install-cron`；cron 与 systemd timer 选择一种，避免重复调度。

`configtest` 目前对目录不存在、防火墙链不可用等情况主要显示提示，不能将退出码 0 当作所有运行条件已满足。安装程序也不会根据 configtest 的失败自动撤销安装或禁用定时任务，因此必须检查输出并完成 dry-run。

升级不会自动清理旧版本可能产生的错误封禁；请根据审计日志人工复核，确认后使用 `swiftban unban <IP>` 解除。默认阈值没有自动调高或降低，字段边界及接口分组变化可能改变候选数量。

## 验证与性能说明

- 本地 macOS + gawk 回归测试 **79 项通过**，防火墙操作全部使用 mock。
- ShellCheck 零告警，覆盖 CLI、库、测试及安装脚本；差异检查通过。
- 覆盖伪造 IP、格式选择、缓存/上游重试、时区边界、字段排除、接口分组、轮转去重、3 分钟文件筛选、故障中止、安装加载和可选 IPv6。
- GitHub Actions 的 Ubuntu CI 执行同一套 ShellCheck 和回归测试；mock 测试不能替代目标机器上的真实 iptables、Docker 网络及生产日志验收。

本版本以正确性为重点，不承诺整体加速。此前本机对比中，单个全部位于窗口内、查询参数各不相同的 10 万行 NPM proxy 样例（约 22 MiB），完整收集/解析/统计耗时三次中位数为旧版 19.53 秒、新版 19.83 秒；统计阶段加快，但结构化解析与去重增加开销，峰值单进程 RSS 约从 15 MiB 增至 117 MiB。该对比不包含真实防火墙，且在加入 3 分钟文件预筛选前完成；对于刚修改的单个文件，预筛选不会减少其内部读取量。

3 分钟筛选可减少长期未修改历史文件的读取，但持续写入的大文件仍会完整读取，内存随窗口内不同记录和接口分组数增长。以上 macOS 合成样例不能直接推算 Linux 生产性能，请按实际日志规模验证耗时、内存及临时磁盘空间。
