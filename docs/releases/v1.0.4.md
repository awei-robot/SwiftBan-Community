# SwiftBan 社区版 v1.0.4

v1.0.4 增加 WATCH 观察列表、单 IP 原始访问复核和手动 IP 来源地查询，并将单接口高频规则调整为只观察。安装和 IPv6 可选链检查也有所改进。

## 主要更新

### WATCH 观察列表

使用 `swiftban watch` 查看近24小时正式扫描观察结果，默认最多50项。支持按 IP、规则、时间和数量筛选；`--dry-run` 切换到演练记录，`--json` 导出 JSON。正式和演练记录独立保存，默认保留7天。查询结果聚合单轮计数、峰值、首次/最后命中时间和扫描轮次，不把重叠扫描窗口的请求数相加。

```bash
swiftban watch
swiftban watch --ip 123.114.230.31 --since 7d --limit 100
swiftban watch --rule api --json
swiftban watch --dry-run
```

### 单 IP 原始访问复核

`swiftban list --ip <IP>` 查询日志目录中全部可用的未压缩访问日志，不限制文件修改时间或默认检测窗口。显示来源文件、行号及原始访问日志，按日志时间从早到晚排列，支持 IPv4、IPv6、可选时间范围和数量限制。客户端 IP 从解析后的日志字段匹配，不会把 URI、UA 或 Referer 中出现的地址当作客户端。

```bash
swiftban list --ip 221.229.164.96
swiftban list --ip 221.229.164.96 --since 7d --limit 200
```

压缩及已删除日志无法查询；原始日志复核与自动检测文件范围不同。自动扫描仍只读取最近3分钟修改的支持格式文件。

### 手动来源地查询

来源地缓存不参与封禁判断。扫描、`list`、`watch` 和 `doctor` 默认均不联网。使用以下命令手动补全：

```bash
sudo swiftban geo refresh
sudo swiftban geo refresh --ip 8.8.8.8
sudo swiftban geo refresh --ip 8.8.8.8 --force
swiftban geo show 8.8.8.8
```

成功缓存有效7天，失败后退避1小时并保留此前成功数据；每轮最多请求30个地址，可再次运行继续处理。封禁列表和 WATCH 仅在显式增加 `--geo` 后读取缓存：

```bash
swiftban list --geo
swiftban watch --geo
swiftban watch --geo --json
swiftban list --geo --ip 8.8.8.8
```

归属地功能需要可选依赖 `curl`、`jq`。安装程序会逐项检查并提示缺失情况，但不会因此阻止检测和封禁。缓存保存在 `${STATE_DIR}/geo/`。

来源地使用 ip-api 免费 HTTP API。官方说明限制每个出口 IP 每分钟45次请求且不允许商业用途；查询会向该服务发送目标 IP。来源地代表网络归属信息，不代表用户真实地理位置。

### 封禁规则与安装体验

单接口高频（`LIMIT_API`，按 IP、域名、完整 URI 统计窗口内总量）与单接口速率（`LIMIT_API_RATE`）均只记录 WATCH，不单独封禁，以降低共享 NAT 出口误伤。其他检测规则仍可独立封禁同一 IP。

安装程序显示现有日志目录和防火墙链，并允许按当前部署环境修改。缺少 IPv6 对应防火墙链时提示并跳过 IPv6，不阻断 IPv4 检测。

## 升级方式

备份 `/etc/swiftban/swiftban.conf` 和 `${STATE_DIR}`，然后获取 v1.0.4 并重新安装：

```bash
git fetch origin
git checkout v1.0.4
sudo ./install/install.sh
```

安装过程中确认日志目录和防火墙链。安装完成后先执行 `sudo swiftban configtest`、`sudo swiftban doctor`；检查原始访问详情用 `swiftban list --ip <IP>`，首次来源地查询用 `sudo swiftban geo refresh`。旧版本已有的封禁和 TTL 会保留。WATCH 结构化历史从升级后的完整扫描开始记录，升级前的终端 WATCH 文本不补录。
